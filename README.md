# Виртуальный практикум кафедры биофизики (СФУ)

Статический сайт с интерактивными лабораторными работами (HTML-симуляторы) и
методическими указаниями. Не требует сервера, баз данных и сборки — работает на
GitHub Pages «как есть».

## Структура

```
.
├── index.html                        # главная страница
├── assets/
│   └── css/style.css                 # общие стили (Inter + фирменные цвета СФУ)
├── docs/
│   └── metodichka_neuroevolution.docx  # методички (.docx / .pdf)
└── labs/
    ├── index.html                    # каталог лабораторных
    ├── lab01-fieldwork/
    │   ├── index.html                # паспорт ЛР №1 (полевая: пробоотбор)
    │   └── hydro-point.html          # «Точка отбора» — полевые карты (смартфон)
    ├── lab02-neuroevolution/
    │   ├── index.html                # паспорт ЛР №2
    │   └── neuro-maze.html           # симулятор нейроэволюции
    ├── lab03-bios3/                  # БИОС-3: браузерная + настольная (.py)
    ├── lab04-kalibr/                 # КАЛИБР: морфометрия SEM (браузер)
    ├── lab05-evolution/              # Эволюция 3D (файл симулятора добавить!)
    └── lab06-fire/                   # Огненный фронт (Python, скачивание)
```

Принцип: **одна работа = одна папка** `labs/labNN-название/` с паспортом
(`index.html`) и файлом симулятора. Методички лежат в `docs/`.

> Имена файлов и папок — только латиницей, без пробелов. Кириллица в URL
> кодируется в вид `%D0%BD%D0%B5...` и ломает ссылки при копировании в Moodle.

## Публикация на GitHub Pages

1. Создайте репозиторий (например, `biophys-labs`) на github.com.
2. Загрузите в него содержимое этой папки (через веб-интерфейс «Add file →
   Upload files» или `git push`).
3. В репозитории: **Settings → Pages → Build and deployment**:
   - Source: *Deploy from a branch*;
   - Branch: `main`, папка `/ (root)` → **Save**.
4. Через 1–2 минуты сайт будет доступен по адресу
   `https://<ваш-логин>.github.io/biophys-labs/`.

Прямые ссылки, которые понадобятся для е-курса:

| Что | URL |
|---|---|
| Каталог работ | `https://<логин>.github.io/biophys-labs/labs/` |
| Паспорт ЛР №1 | `https://<логин>.github.io/biophys-labs/labs/lab01-fieldwork/` |
| «Точка отбора» (ЛР №1) | `https://<логин>.github.io/biophys-labs/labs/lab01-fieldwork/hydro-point.html` |
| Паспорт ЛР №2 | `https://<логин>.github.io/biophys-labs/labs/lab02-neuroevolution/` |
| Симулятор ЛР №2 | `https://<логин>.github.io/biophys-labs/labs/lab02-neuroevolution/neuro-maze.html` |
| Методичка | `https://<логин>.github.io/biophys-labs/docs/metodichka_neuroevolution.docx` |

Обновление сайта = обновление файлов в репозитории; Pages пересобирается
автоматически при каждом коммите.

## Как добавить новую лабораторную работу

1. Скопируйте папку любой готовой работы → `labs/labNN-<название>/`.
2. Замените `neuro-maze.html` на HTML-файл нового симулятора (латинское имя).
3. Отредактируйте `index.html` в папке работы: заголовок, цели, порядок,
   контрольные вопросы, имя файла симулятора и методички.
4. Положите методичку в `docs/`.
5. Добавьте карточку работы в `labs/index.html` и (по желанию) на главную —
   образец карточки уже есть в разметке (блок `LAB-02 · готовится`).

## Статусы работ

Карточка каждой работы несёт статус: **доступна** (есть методичка, обкатана) ·
**тестируется** (приложение выложено, методичка пишется) · **готовится**
(страница есть, файла ещё нет). Статус меняется правкой одной строки в
карточке (`labs/index.html`): класс `status` / `status test` / `status soon`
и текст рядом.

## Обложки карточек

Карточки работ на главной и в каталоге показывают обложку из `assets/img/`
(`lab01-cover.svg`, `lab02-cover.svg`). Сейчас это рисованные SVG-заставки в
палитрах самих приложений. Лучший вариант — заменить их скриншотами:

1. Откройте приложение, приведите экран к показательному виду.
2. Сделайте скриншот, обрежьте до соотношения ~2:1 (например, 1200×600).
3. Сохраните как `assets/img/lab01-cover.jpg` (или .png) и поменяйте
   расширение в `src` карточек в `index.html` и `labs/index.html`.

Высота обложки в карточке — 148 px, картинка кадрируется по центру
(`object-fit: cover`), поэтому главный объект держите в середине кадра.

## Настольные версии (.exe): раздача через облако

.exe-файлы в репозиторий не кладём — они раздаются по внешним ссылкам
(Яндекс.Диск, Google Drive, облако Mail.ru). На странице БИОС-3 кнопка уже
стоит, в ней заглушка `https://REPLACE-cloud-link` — замените на свою ссылку.
Для Яндекс.Диска давайте публичную ссылку «Поделиться» как есть; студент
увидит стандартную страницу скачивания.

Напоминания:
- .exe собирается только на Windows (PyInstaller не кросс-компилирует);
  порядок — в `build_windows.bat` внутри «Экоэнергетики». ONEDIR-в-ZIP
  предпочтительнее ONEFILE: быстрее стартует и реже раздражает антивирусы.
- Неподписанный .exe вызовет предупреждение SmartScreen — подсказка для
  студентов уже стоит на странице БИОС-3.

## Кодовые слова (доступ к работам)

Кнопки запуска на странице каждой работы закрыты «шторкой»: студент вводит
кодовое слово, которое преподаватель выдаёт на занятии. Доступ действует до
закрытия вкладки. Стартовые слова (смените перед семестром!):

| Работа | Кодовое слово |
|---|---|
| ЛР №1 Точка отбора | енисей |
| ЛР №2 Нейро-лабиринт | синапс |
| ЛР №3 БИОС-3 | хлорелла |
| ЛР №4 КАЛИБР | ферет |
| ЛР №5 Эволюция | мутация |
| ЛР №6 Огненный фронт | перколяция |

Слова не чувствительны к регистру. Как сменить: откройте сайт, нажмите F12 →
Console, выполните `gateHash('новое слово')`, полученный хэш вставьте в
таблицу `HASHES` в файле `assets/js/gate.js` напротив нужной работы.

**Честное ограничение:** это организационная шторка, а не защита данных.
Сайт статический, файлы работ доступны по прямым URL тому, кто их знает.
Если нужен настоящий контроль доступа — ставьте пароль на элемент е-курса
в Moodle и давайте ссылки только внутри курса.

## Связка с е-курсами (Moodle, e.sfu-kras.ru)

Три способа, от простого к сложному:

1. **Гиперссылка** (рекомендуется). В е-курсе: «Добавить элемент или ресурс →
   Гиперссылка», вставьте URL паспорта работы. Внешний вид: «Открыть»
   или «Во всплывающем окне». Плюс: всегда актуальная версия, ноль возни.
2. **Встраивание через iframe.** Элемент «Страница» (или любое поле с
   HTML-редактором), кнопка `</>` (HTML-режим), вставьте:
   ```html
   <iframe src="https://<логин>.github.io/biophys-labs/labs/lab01-neuroevolution/neuro-maze.html"
           width="100%" height="800" style="border:0;" allowfullscreen></iframe>
   ```
   GitHub Pages отдаёт страницы по HTTPS и не запрещает встраивание, поэтому
   iframe в Moodle работает. Симулятор полноэкранный, поэтому задайте
   высоту не меньше 700–800 px.
3. **Загрузка файла симулятора прямо в Moodle.** Ресурс «Файл», загрузить
   `neuro-maze.html`, в настройках отображения выбрать «Открыть». Подходит,
   если нужна работа без внешних ссылок, но обновлять придётся вручную в
   каждом курсе.

Методичку в е-курс лучше добавлять ресурсом «Файл» (студенты привыкли), либо
давать прямую ссылку на `docs/…​.docx` с сайта.

## Замечания

- Шрифт Inter подключён с Google Fonts; при работе офлайн сайт автоматически
  откатывается на системный шрифт — вёрстка не ломается.
- Симулятор нейроэволюции полностью автономен (один HTML-файл), его можно
  раздавать студентам и для офлайн-работы. «Точке отбора» для загрузки карты
  нужен интернет (Leaflet и картографические тайлы подгружаются из сети),
  поэтому в поле у студентов должна быть мобильная связь.
